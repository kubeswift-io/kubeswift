## The UI's Start: William's, in the browser

1. **Set up a guest to start.** Create a small guest, or use any running
   test guest, and wait for `Running`.
2. **Power it off from inside,** over SSH or the UI console: `sudo systemctl
   poweroff`.
3. **Confirm it stopped.** In the UI the guest should show **Stopped**
   (`kubectl get swiftguest` phase `Stopped`, launcher pod `Succeeded`).
4. **Press Start** in the UI.
5. **Expect it back.** Within about 15 s a **new** launcher pod exists
   (check its UID), the guest goes Scheduling → Running, and it gets an IP.
   The UI console connects.
6. **Press Start again** while it runs. Nothing should restart: the same pod
   UID, and uptime keeps counting.
